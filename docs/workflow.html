How It Works

A simple workflow that connects daily contributions, consistent practice, and long-term reflection.

1. Daily Execution

The daily routine is designed to be lightweight. When possible, aim for roughly 30–60 minutes. Adjust the time to fit your circumstances.

  1. Open a developer platform, such as GitHub.
  2. Pick one small thing to work on.
  3. Spend some time making progress.
  4. Make a contribution.
  5. Record what you did in your daily log.
  6. Reflect when useful.

The routine is a guideline, not a strict schedule. The important part is showing up and making meaningful progress.

2. Contribution Levels

Not every day needs the same amount of effort. These three levels provide a flexible way to think about contribution size and commitment.

Level 1 — Lightweight

For busy days or smaller contributions.

  • Comment on an issue.
  • Review a pull request and provide feedback.
  • Improve documentation or fix a typo.
  • Work on a private repository.

Level 2 — Standard

The normal contribution target.

  • Submit an issue.
  • Prepare or edit a pull request.
  • Reproduce a bug and document it.
  • Add an example or test case.
  • Make meaningful progress on your own project.

Level 3 — High Value

Larger contributions that require more time and effort.

  • Submit a pull request.
  • Implement a feature or significant improvement.
  • Refactor a complex section of code.
  • Write a detailed tutorial or guide.
  • Propose a new design or feature.
Suggested rhythm
  • Every day: at least Level 1.
  • 1–2 days a week: Level 2.
  • 1–2 days a month: Level 3.
These are guidelines, not requirements.

3. Recovery Mode

Life gets busy. Work, travel, unexpected events, and other responsibilities can make a normal contribution unrealistic.

Level 1 — Last Resort Only

Recovery Mode provides a lightweight fallback when time or energy is very limited.

  • Read an issue or pull request and leave a thoughtful comment.
  • Review a repository's structure or contribution guidelines.
  • Read code and record at least one insight in your daily log.
  • Explore a useful open-source project briefly.
  • Optionally work on a private repository.

Use this mode only when necessary, and record the activity in your daily log.

4. Reflection Cycles

Different timeframes help you see your progress from different perspectives.

Daily

What did I work on today? What did I learn?

Weekly

What progress did I make? What challenged me?

Monthly

What patterns emerged? What do I want to explore next?

Yearly

How have I grown? What direction do I want to take?

Progress Happens Over Time.

Small contributions, repeated practice, and regular reflection create opportunities for long-term growth.
